Venue weather and lightning links

The app owner maintains constants/venueLightning.ts as a fallback registry.
It includes the owner-provided Earth Networks page labeled
Dr Phillips Park, bound to existing venue_1l4q16f. The venue identifier was read
from staging on 2026-10-10 without changing a record. The provider label must
remain visible; this URL is not a universal Little League or sports alert feed.

Admin configuration process (requires the client update after Android 32/iOS 20)
1. An active Squad admin opens Squad details, Manage Squad, Weather & Lightning.
2. Obtain the facility's official public weather page and confirm its coverage
   with the venue operator. A link for another facility must not be reused.
3. Enter the venue name, provider name, and public HTTPS link. Select Outdoor
   or Indoor and outdoor. This setting is optional for venues with outdoor use.
4. Preview the exact link, return to the app, and confirm that it covers the venue.
   Changing any draft field invalidates the preview and confirmation.
5. Save once. Only getSquadWeather and updateSquadWeather are required server
   functions. No new native library, Rules, index, or runtime role is required.
6. Admins may edit or remove the link. Concurrent edits require a reload; a failed
   or ambiguous write is never automatically retried. Removal suppresses the
   fallback for that Squad and its linked Teams without deleting old messages.

Settings are saved on the exact Squad, not shared with other Squads at a venue.
Only active, permanent-account Squad admins may write, with App Check and current
account standing enforced. Historic creator status never overrides a demotion.
Server-only change records contain the editor, revision, time, and operation.
Readers receive only venue-link fields, not admin identities or membership data.
Private Squads additionally require active Squad or linked Team membership.
Fresh reads occur on focus/resume, with concurrent requests shared. Removed or
unavailable settings do not display a cached link or an all-clear status.
Once the editor is delivered, individual link changes need no additional build.
Until then, installed Android 32 and iOS 20 retain the existing owner preset.

Placement
- Squad details: the verified venue card is below the Squad identity.
- Parent and Coach team pages: their own team.squadId supplies the venue binding.
  The card identifies it as the Squad venue and warns that away venues may differ.
- A team without a linked approved Squad does not inherit the currently selected
  Squad's weather. Users can open that venue's Squad page directly.
- Event records currently have free-text venue/address, without a verified venue
  identifier. No weather source is inferred for an away event from those fields.

Weather Delay messages
- The Communications template offers an unchecked venue-confirmation checkbox
  only when the selected team's own Squad resolves to a current outdoor source.
  The coach confirms the activity is at that named venue before including a link.
- The optional suffix shows the facility name, full public HTTPS URL, and venue
  safety instructions. Share and the announcement composer receive the same text.
  The coach's existing message and next-update time remain editable and unchanged.
- Venue confirmation is saved separately for each team draft while the screen is
  open. New team drafts do not inherit another team's confirmation or weather URL.
  Unchecking removes the generated suffix, without deleting manually edited text.
- Parent and Coach announcement details make only the current Squad's exact
  weather URL tappable through the provider browser. Replaced and removed links
  remain ordinary text in preserved historical messages.
  Deleted/removed announcements keep their existing visibility checks.
- The link is optional for rain-only delays, indoor activities and away venues.
  No message is sent automatically, and provider status never resumes play.

Provider boundary
The app opens the original HTTPS page using the already-installed
expo-web-browser package. Android uses a browser tab in the app's task; iOS uses
the system browser sheet. Closing/back returns to the originating app screen.
No GPS, account ID, credentials, token, child details, or event data is appended.
The provider receives an ordinary page visit and controls its page/cookies/status.
There is no polling, scraping, local countdown, mirrored safe/unsafe badge, or
automatic Sideline Social lightning push notification.
Browser launch failures have a localized manual Retry. A provider page load or
connection failure is not detected by openBrowserAsync: the card explains how to
handle it and never treats it as all clear. The venue's safety plan governs play.
