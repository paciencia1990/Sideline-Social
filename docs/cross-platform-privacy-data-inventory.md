## Account deletion verification

The in-app path is Profile → Account Settings → Delete Account. It requires `DELETE`, current password reauthentication, a second destructive confirmation, then calls `deleteOwnAccount`, clears AsyncStorage, signs out, dismisses navigation and replaces the route with sign-in. Auth is deleted last so partial cleanup can be retried. The callable uses only `context.auth.uid`, preventing a caller from selecting another account.

Verified cleanup includes Auth, private/public profiles and child subcollections, notification inbox/tokens, friend requests/relationships/blocks, team and Squad membership, team-child links, authored announcements/replies/audio, message content anonymization, conversation membership, RTDB game participation, Trivia participation, reward sessions, activity, Squad administration requests, and Coach AI requests, rolling-limit documents, feedback and feedback limits. Moderation reports are retained with reporter/reported UIDs nulled. Sole active team owners/Squad administrators are blocked until succession is safe.

The audit found and locally corrected identifier retention in Squad season totals, season creator/closer fields, friend-conversation participant/admin/name maps and message visibility arrays, and private-team participant arrays (`functions/src/accountDeletion.ts`). The corresponding emulator fixture now asserts cleanup. **These corrections are not deployed by this audit.**

Provider backups, Cloud Logging, Firebase Authentication operational records, and moderation-report retention periods require owner/provider/legal confirmation. A public web deletion-request resource does not yet exist.

## UGC and child-safety status

Implemented: authenticated server writes; rules deny direct client report access; message/user/team-content reporting; friend blocking/unblocking and backend delivery checks; own-message removal; coach/staff reply/announcement moderation; generic pushes; bounded report snapshots; basic severe-content phrase screening; deterministic duplicate reports; child profiles private to parent/authorized team paths.

Not established by code: acceptance of Terms/Community Guidelines before signup or posting; staffed moderation queue; restricted operator console/workflow; approved response SLAs; account sanctions; appeals; formal CSAM/NCMEC process; law-enforcement and imminent-danger procedures; monitored support/safety contact; approved evidence and backup retention. Report documents with `status: open` do not prove an operational moderation program.

The app is described as adult parent/coach oriented and no direct child account fields exist, but signup has no age/adult attestation. Audience/minimum-age language and whether an age gate is required are product/legal decisions.
